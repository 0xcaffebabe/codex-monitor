# codex-monitor

多工作空间 Codex Web 会话观测与交互台。Server 统一提供 Web、账户和工作空间管理，每台机器的 client 主动通过 **ws + AES-256-GCM** 连接 Server，在本机读取会话并执行 Codex 控制。电脑、平板和手机可切换工作空间管理不同 client，也可用多个标签页同时管理。

默认一体启动会自动启动本机 client，并经过真实加密 WebSocket，沿用原有账户和本机数据。独立部署请看 [Server / client 部署与协议说明](docs/server-client.md)。固定 AES 密钥保存在两端本地，重连不派生新密钥；握手使用签名证明，不传密钥。

macOS 支持独立后台 client、原生会话控制与 zsh 项目终端，使用 `./start.sh` / `./stop.sh`。安装、数据范围及桌面互操作说明见 [macOS client](docs/macos-client.md)。

## 直接使用（Windows）

需要 **Node.js 24 或以上版本**。首次启动会安装依赖并生成生产构建。

1. 双击 `start.cmd`，或在此目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1`。
2. 电脑访问 **http://localhost:9902**；同网络手机访问启动信息中的 LAN 地址。
3. 初次启动会生成一次性初始化密钥。通过启动日志中的初始化链接创建管理员。通过命令行创建或重置账户时，临时凭据位于 **`.monitor/initial-credentials.txt`**。
4. 保持勾选“记住此设备”，登录凭据保存在此浏览器本地，有效期 **90 天**。退出、撤销设备、账户删除及到期后需重新登录。不同地址、端口和浏览器分别登录。
5. 双击 `stop.cmd` 停止服务；再次启动仍保留账户和设备授权。

后台启动无额外终端窗口。日志为 `.monitor/server.log` 和 `.monitor/server-error.log`。关闭网页不会停止服务；电脑休眠、关机或服务停止后不可访问。本应用不自动修改开机启动或系统防火墙。

作为独立 client 时可以直接传参，无需编辑 `.env`：

```powershell
# Windows 后台启动
.\start.cmd -Mode client -ServerUrl "ws://server-address:9902" -WorkspaceId "工作空间ID" -ClientKey "AES密钥"
# 或跨平台前台启动
npm run client -- --server-url "ws://server-address:9902" --workspace-id "工作空间ID" --client-key "AES密钥"
# 停止后台 client
.\stop.cmd -Mode client
```

支持密钥文件、Codex 目录、数据目录及桌面监测参数；命令行优先于环境变量，Windows 启动器再以 `.env` 补充。Client 日志默认位于 `.monitor-client`。运行 `start.cmd -Help` / `npm run client -- --help` 查看参数，完整示例见 [Client 命令行启动](docs/server-client.md#client-命令行启动)。

## 使用方式

- **工作空间**：顶栏选择器切换 client，显示在线／离线状态；管理员点击旁边“管理工作空间”可添加 client、保存连接配置、修改名称及轮换密钥。切换会终止旧页面请求，草稿、附件及待确认操作按工作空间隔离。以下“本机”指当前工作空间对应的 client 机器。
- **全部会话**：按时间或项目查看；搜索标题、目录、首条消息、摘要或会话 ID；按项目、进行中及归档状态筛选。默认隐藏内部子代理，可勾选“子代理”显示。
- **详情**：提问、AI 回复和进展更新统一按时间展示。连续的工具调用与思考摘要归入默认收起的执行分组。工具调用优先显示 Codex 记录的操作标题，分组显示最后一次工具调用的标题；没有标题时沿用工具名与“执行过程”。标题末尾显示该组最新工具调用时间（精确到秒）；展开后可逐项查看原始工具名、调用参数、耗时、失败状态及思考摘要。搜索当前已加载内容时包含操作标题，并自动展开命中的记录；导出 Markdown 同样保留操作标题。
- **项目终端**：管理员在会话详情顶部点击“终端”，从当前会话的项目目录启动真实 Shell（Windows 使用 PowerShell，Linux/macOS 使用 client 的默认 Shell）。直接在终端区域输入或粘贴命令，Enter 执行，方向键编辑与查看历史，Tab 补全，Ctrl+C 中断。支持连续命令、交互程序、实时输出、中文、滚动和调整窗口。切换工作空间后，命令在对应 client 机器执行。关闭终端、切换会话、退出登录或 client 断连会结束终端；浏览器意外断开后最多保留 10 分钟。Shell 状态和输出仅在当前终端生命周期内保留，重新打开从会话项目目录开始。
- **代码变更与审查**：管理员在会话详情顶部点击“变更”，查看该会话项目所在 Git 仓库的未提交变更。支持全部变更（相对 HEAD）、已暂存、未暂存（包含未跟踪文件）、文件筛选、逐行 diff 和已读标记。刷新会清除已读标记；二进制文件显示提示，大文件最多展示 512 KiB / 5000 行。点击“让 Codex 审查”或文件标题旁的审查按钮，可编辑审查要求并发送到当前会话，Codex 重新读取所选范围的最新代码进行审查，结果显示在会话中。Git 在对应 client 上只读运行，需要本机安装 Git。
- **历史分页**：进入详情先加载最近 70 条原始记录，向上滚动接近顶部时自动加载更早记录，并保持当前阅读位置。执行记录折叠后不足一屏时，也可用向上滚轮、手指向下滑动或时间线内的 Home / Page Up / ↑ 键触发；开始阅读历史后会继续越过不增加可读高度的分页。加载失败可点击重试。思考记录中没有可读摘要的条目不会显示，因此显示数量可能小于原始记录数。
- **实时同步**：client 每 1.5 秒检查本机持久化记录，经加密 WebSocket 发往 Server，再通过带认证的 SSE 通知浏览器。Client 与浏览器均支持断线重连；页面每 15 秒校准索引。向上滚动暂停自动跟随，“回到最新”恢复。
- **PC 布局**：进入详情后导航默认收成图标栏，顶栏可展开导航、收起会话列表或进入专注模式，Esc 退出专注。窄窗口的会话列表使用抽屉，选择会话后自动关闭；导航与宽屏列表的手动选择在浏览器中保存，“恢复自动布局”重新按当前尺寸分配空间。详情中的“详情”可展开完整路径、模型和会话用量。完整规则见 [PC 全局适配方案](docs/desktop-layout.md)。
- **对话目录**：1800px 起默认显示右侧目录，其他尺寸通过目录按钮展开；详情实际宽度不足时自动使用浮层。包含整段会话的提问、回复摘要、执行轮次与工具调用数量。点击目录会自动加载对应历史并定位，浮层定位完成后收起。终端图标复制恢复命令，下载图标导出 Markdown。
- **手机会话切换**：点右侧固定按钮查看所有工作空间的进行中会话，按空间分区显示名称、数量、会话标题、项目及最后活跃时间（如几秒前、几分钟前）。列表每 3 秒同步，展开时活跃时间每秒更新；点击目标会话会自动切换到对应空间并收起列表，当前空间与会话分别标记。
- **iOS 屏幕常亮**：通过 HTTPS 在 iOS Safari 16.4 及以上版本打开，进入会话详情后自动申请保持屏幕常亮，不受会话是否正在执行影响。返回列表、退出登录或切到后台时释放，回到前台后重新申请；详情工具栏显示实际申请状态，系统暂停后可点“重试常亮”。普通局域网 HTTP 地址无法使用此能力，会显示“常亮需 HTTPS”；低电量模式等系统策略仍可能拒绝或释放常亮。添加到主屏幕的 Web App 需要 iOS / iPadOS 18.4 及以上版本，并受对应系统版本的 WebKit 支持情况影响。
- **图片预览**：消息正文中的本地 Markdown 图片直接显示缩略图，支持中文、空格路径及引用式图片，点击放大；“查看图片”记录中的连续图片合并展示。消息、Computer Use 截图及附件缩略图按浏览器实际解码能力优先使用 AVIF，回退 WebP 或原格式。先加载最多 720 × 480 的缩略图，点击后加载最多 2560 × 2560 的清晰预览；可点“查看原图”读取未压缩文件。压缩在图片所在 client 完成，原文件及发送给 Codex 的附件内容保持不变；动图、编码失败或压缩后体积变大的图片使用原图。每个 client 缓存最多 32 MiB／128 份预览，有效期 5 分钟，源文件变化会失效。图片接口验证当前登录，只提供这条会话中明确引用或实际查看过的图片，不接受任意文件路径。支持 PNG、JPEG、WebP、GIF、BMP、AVIF，单张最多 20 MB；文件缺失会显示原因，“查看图片”记录会尝试读取会话中保存的图片。
- **上下文**：详情显示最近模型调用的上下文 Token、可用上限及百分比，随记录更新；使用输入加输出 Token，缓存和思考不重复相加。没有可用上限或最近使用记录时明确显示未知，不以整个会话的累计用量代替。
- **上传附件**：管理员可在会话输入框或新建会话页点“添加附件”，多选图片或文件；也可在消息框中直接粘贴剪贴板中的图片或文件，或将文件拖入消息输入区，自动上传并加入附件。拖入时显示投放提示，连续粘贴或拖入会依次上传。普通文字仍按原样粘贴；文件粘贴取决于浏览器是否提供剪贴板文件内容。每条消息最多 10 个附件、单个不超过 20 MB。图片显示缩略图，发送前可移除。上传完成后，服务端会将文件绝对路径附到提示词末尾，也支持只发送附件；发送失败、排队或刷新页面时保留当前浏览器标签页的附件草稿。斜杠指令及目标设置不附带文件。
- **访问管理**：创建管理员或只读访问者，撤销自己的设备，修改密码。只读访问者可读所有本机会话，不可管理账户。每位用户只能撤销自己的设备。修改密码会撤销其他设备；删除用户会撤销其所有设备。
- 支持浅色与深色模式，主题同样保存在浏览器本地。
- **用量统计**：侧栏进入，按近 24 小时、7 天、30 天、全部或自定义日期统计；可筛选模型、项目及是否包含子代理。展示成本、请求数、Token、缓存命中率、首字均值和 TPS，支持小时/日趋势、53 周热力图、模型分布和请求分页。点击请求的会话名称可进入详情，详情中的“会话用量”可展开查看指标。

## 用量与计价口径

只读扫描 `sessions` / `archived_sessions` 下的 `.jsonl` 与 `.jsonl.zst`；压缩记录直接流式读取，不生成解压文件。首次进入用量页会建立 `.monitor/usage.sqlite` 本地缓存，期间显示扫描进度及已扫描部分统计；完成后每 15 秒检查增量。普通日志从上次完整行继续读取，压缩历史按文件变化重读，缓存跨重启保留。已归档记录和默认勾选的子代理均纳入；重复快照、压缩/普通副本、分叉中复制的父会话历史不会重复统计。统计仅覆盖本机仍保留的用量日志，不保证与订阅账单、代理导入历史或会话列表的 `tokens_used` 数值相同。

- **请求**：优先使用逐请求 `token_usage_record`，兼容旧 `token_count.last_token_usage`；缺少逐请求值时按累计值差额计算。模型切换读取 `turn_context` / `thread_settings_applied`。远程压缩产生的独立用量也计入。
- **Token**：输入包含缓存读取和缓存写入；输出包含思考。消耗 Token = 输入 + 输出，不再重复加缓存或思考。缓存命中率 = 缓存读取 / 输入。新增输入 = 输入 − 缓存读取 − 缓存写入。
- **首字**：输出项的 `started_at_ms` − 请求前最近的输入/上下文/工具结果起点，属于日志估算。没有开始时间时显示“—”，不会把消息保存时间当作首字。轮次级 `task_complete.time_to_first_token_ms` 不冒充每个请求的首字。
- **TPS**：输出 Token / 生成秒数，优先扣除首字等待；缺少首字时用完整请求耗时，可能包含等待。工具完成后的下一次请求从工具结果重新计时，排除已完成工具的运行和轮次间空闲；旧日志延迟到工具完成才写用量时，使用最后输出时刻结束计时。页面用 `≈` 明示估算；均值按有效样本统计，TPS 按输出及耗时加权，展示样本数。
- **成本**：`(新增输入 × input + 缓存读取 × cachedInput + 缓存写入 × cacheWrite + 输出 × output) / 1,000,000`，单位 USD。未定价模型显示“未定价”，汇总以 `+` 提示仅含已定价部分。无有效时间的记录保留 Token 和成本。

价格集中在 [`config/model-pricing.json`](config/model-pricing.json)，初始值参考本机 CC Switch 的手动价格表，单位为 **USD / 百万 Token**。直接修改 `models` 中的四项价格即可；`aliases` 可显式指定模型别名。修改后下一次刷新会重算历史成本，无需重启或重扫日志；无效配置保留上次有效值并提示。可通过 `MONITOR_PRICING_FILE` 指定其他价格文件。不自动下载或更新价格，不将估算标为实际扣费。

## 会话交互与常用指令

Windows 一体模式和独立 client 默认在启动时立即检查 Codex 桌面版，之后每 15 秒检查一次；同一 Windows 登录会话中桌面主进程不存在时自动拉起。检测区分桌面程序与 CLI、后台 App Server 及 Electron 子进程；已有桌面不会重复启动。每次启动请求或失败后至少等待 60 秒再尝试启动，启动失败写入监控日志，不影响历史读取。关闭监控服务后停止检查，已运行的 Codex 桌面版继续保留。纯 Server 模式及其他操作系统不启用此功能。

可在 client 机器的 `.env` 设置 `MONITOR_CODEX_AUTOSTART=false` 关闭自动拉起，或用 `MONITOR_CODEX_CHECK_MS` 调整检查间隔（1,000–300,000 毫秒）。默认自动发现 Windows Store 安装及常见独立安装目录；其他安装方式通过 `MONITOR_CODEX_DESKTOP` 指定桌面 GUI 程序的绝对路径，例如 `C:\path\to\app\ChatGPT.exe`，不能填 `resources\codex.exe` 等命令行程序。配置修改后需重启监控 client；主动退出 Codex 后，只要自动监测仍启用，它就会再次拉起。

桌面版启动并登录后，以管理员身份登录监控台；沿用 Codex 已登录账户和会话设置，无需另配 OpenAI API Key。只读访问者不能发送消息、新建或执行指令。

Windows 和 macOS 默认共用 App Server 会话控制。新建会话可选择完全访问（默认）、沿用本机配置、只读、项目写入或项目写入并允许联网。受限模式下，由 Monitor 承载的会话可在网页处理命令、文件修改和额外权限审批；桌面持有的会话仍在桌面确认。升级需重新构建并重启 Server 和 client，详见 [会话控制与审批](docs/native-control.md)。

- **发送消息**：详情底部输入消息，运行中追加到当前轮次，空闲时开始新一轮。会话结束后，可在“添加附件”旁选择下一轮的模型和思考级别；默认沿用当前会话设置。执行中追加消息沿用当前配置；服务端在提交前复核状态，防止误切换。新建与继续会话的消息框均支持 Enter 发送、Shift+Enter 换行，也支持 Ctrl / ⌘ + Enter，每条最多 12,000 字符；回执表示 Codex 已接收，执行与回复继续显示在时间线。手机上的“＋”展开更多会话操作。
- **停止当前执行**：点击发送按钮右侧的方形停止按钮，中断当前轮次（也可中断上下文压缩）；空闲时按钮置灰。行为与 Codex 桌面版停止操作一致，有正在执行的目标时会一并暂停。操作绑定点击时的轮次，避免误停随后启动的新一轮；回执不确定时可查询原操作结果。
- **新建会话**：点击“新建会话”进入空白会话详情页，从 Codex 已保存的本机项目中选择项目并发送首条消息，也可上传附件或将首条消息设为目标；可指定模型和思考级别。发送成功后直接显示新会话的详情。模型列表从本机 Codex 动态读取，思考级别随模型变化；默认沿用 Codex 设置，选择模型后可指定思考级别。会话同时出现在桌面版和监控台。已有会话的追加消息沿用原会话设置。
  勾选“将首条消息设为目标”，填写最多 4,000 字符的目标正文，点击“创建并执行目标”；也可直接输入 `/goal 目标内容`。首条消息启动执行后会保存 Codex 原生目标，可携带附件，目标模式随草稿保留。若目标保存失败或结果待确认，弹窗会保留已创建会话，可“重试保存目标”或“打开已创建会话”；重试先核对当前目标，保留已完成、暂停或被修改的目标，不重复创建会话或追加执行消息。
  若创建成功时本地记录尚未同步，详情显示“新会话已创建，正在同步记录…”并每秒自动重试，刷新页面也会继续等待。单次等待最多 45 秒，超时可重试，无需重复创建；同步识别以两分钟内的成功回执为准。
- **提问记录**：通过网页或其他会话启动、追加的提问，会作为用户消息显示在对话和目录中，导出 Markdown 时一并保留。
- **压缩上下文**：点击“压缩上下文”或发送 `/compact`，执行原生压缩。需等待当前轮次结束；桌面持有的会话交给原实例，未加载会话在确认没有 owner 后由 Monitor 恢复；以时间线中的压缩完成记录为准。
- **压缩期间排队**：压缩中仍可提交普通消息，服务端按提交顺序等待，压缩结束后自动发送。页面显示排队状态并自动查询，尚未提交给 Codex 的消息可取消；取消后保留输入内容。刷新页面或重启监控服务会保留等待中的消息。已提交但回执不确定的请求保留为待确认，先核对会话记录。
- **目标**：已设置的目标固定显示在输入框上方，单行显示，过长以省略号结尾；同一行显示 Codex 记录的累计执行时长，每 10 秒同步一次。点击文字查看完整目标，点击铅笔修改（自动带入当前内容），旁边可暂停／继续或停止目标。暂停保留目标；停止清除目标，两者都不打断当前轮次。也可通过“目标”按钮设置最多 4,000 字符的 Codex 原生目标。支持 `/goal`（查看）、`/goal 目标内容`（设置并执行）、`/goal pause`、`/goal resume`、`/goal clear`、`/help`。
- **断线恢复**：消息、新建和指令使用持久化请求 ID 防止重复提交。刷新后可查询原请求结果；结果待确认时先核对会话记录。草稿和待确认请求保留在当前标签页的会话存储中。

运行中会话由 Monitor 自有运行时或可连接的原桌面实例管理，其他客户端正在执行的会话会被拒绝；归档与内部子代理会话保持只读。历史空闲会话在确认没有 owner 后可由 Monitor 恢复。控制接口与 Codex 版本有关，升级后需核对兼容性。`MONITOR_CODEX_CLI` 可指定 Codex CLI，默认自动查找桌面自带运行时；显式配置 `MONITOR_CODEX_PIPE` 会选用旧 tools 通道，该通道不提供网页审批。

默认通道发送前通过会话元数据、原 owner 确认及本地轮次状态判断是否执行中或压缩中；旧 tools 通道继续读取桌面会话列表。状态检查不加载整轮工具输出，单轮工具记录过大也不会因历史读取上限禁用消息或指令。

自动测试使用独立临时数据和模拟桌面服务；真实模型验证另在用户授权的 `work` 项目会话执行。测试任务可配置 `MONITOR_TEST_PORT`、`MONITOR_TEST_ROOT`、`MONITOR_TEST_PUBLIC_DIR` 隔离端口、临时数据和前端构建；临时目录必须位于系统临时目录中，且名称以 `codex-monitor-` 开头。

## 数据和实时性的边界

附件保存到服务端系统临时目录中的 `codex-monitor-uploads-*` 文件夹，文件名包含随机 ID；不同监控数据目录使用独立的附件目录。附件读取和删除需要登录且属于当前上传账户，只读访问者不可上传。服务最多同时处理 4 个上传，同一账户最多 2 个；单次上传超时为 2 分钟，中断或超限会清理未完成文件。移除未发送附件会删除临时文件；已提交的文件保留供 Codex 读取，服务重启不会主动删除，系统清理临时文件后需重新上传。本功能传递本机路径，由 Codex 读取文件内容。

只读打开 `CODEX_HOME`（默认当前用户的 `~/.codex`）下版本号最高的 `state_*.sqlite` 与 `thread_history_*.sqlite`，兼容 WAL 下的 Codex 同时写入。索引读取 `threads`，执行状态读取 `thread_turns`，内容读取 `thread_items` 与 `thread_realtime_items`。旧版本或没有执行数据库的环境，回退到 `sessions` / `archived_sessions` 中的 JSONL，并读取 `session_index.jsonl` 标题。

**实时显示的是 Codex 已经写入本机的记录**，不是模型尚未持久化的逐字 token。部分 Codex 版本会在一条消息或工具执行结束后才保存内容，监控页无法提前取得这些内容。未结束轮次若 15 分钟没有索引更新，会标为“状态待确认”，避免把崩溃或退出前的残留状态当作正在执行。不会解密内部推理。控制操作通过本机 Codex 桌面通信与 App Server 接口执行，由 Codex 自身保存记录；监控台不直接改写 Codex 数据库或会话日志。

工具调用只显示参数、状态和耗时，不返回或渲染结果正文；参数最多保留首尾约 2,000 字符，中间标注省略；AI 正文沿用 100,000 字符的单条上限。JSONL 普通文本单行超过 8MB 时在读取过程中跳过；相同版本的旧日志并发请求共享一次解析。会话正文中的本地图片与“查看图片”记录通过受保护接口显示，外部图片链接不自动加载。大响应启用压缩；详情请求依次处理并合并重复实时通知，避免慢网络下始终加载。实时连接共用索引轮询，相同会话每轮只检查一次版本。目录或文件缺失会展示提示。

有 Computer Use 操作的会话会在标题旁显示 **操作回放**（手机端为显示器图标）。点击打开独立时间线，按时间选择操作，查看操作标题、状态、耗时、页面信息和对应截图；支持前后切换、多张截图、点击放大和加载更早操作。打开期间随会话更新，保留正在查看的历史步骤。没有完整截图的步骤显示明确提示。

Computer Use 时间线按需读取，支持 `cua_repl` 和通过 `node_repl` 使用 `@oai/sky` 的操作。截图优先从 JSONL 工具返回恢复，忽略数据库中带截断标记的图片和外部图片 URL；不会把相邻操作截图当作本步骤画面。截图通过已有登录认证获取，列表不包含图片二进制或原始操作脚本；独立视图可展开工具实际返回的页面文字。日志按字节位置增量索引，选择截图时只读取对应记录，最多缓存 8 个会话的索引，不缓存截图正文。Computer Use 单行记录上限为 32 MB，过大的记录会跳过并提示。

用量汇总以每批 2,000 条记录读取，按时间和 ID 翻页，避免一次分配全部原始记录或使用大 OFFSET。最多缓存 16 组筛选结果；用量记录、价格配置、会话名称或项目归属变化时重新汇总。仅追加工具输出或进展记录时保留汇总缓存。

## 网页完成通知

登录后，页面每 3 秒同步 Server 当前尚未关闭的通知列表；主会话每一轮成功完成时，在右下角显示可点击的通知卡片，包含会话标题、工作空间和完成时间。点击“查看会话”会先等待 Server 确认移除该通知，再打开对应工作空间的会话，支持跨工作空间跳转。此功能默认开启，独立于 Webhook 开关及投递结果，支持 HTTP，无需浏览器通知授权或 Service Worker。

待通知列表由 Server 内存统一管理，最多保留最近 50 条，同屏显示最多 3 条。任意已登录端逐条关闭、全部关闭或通过通知打开会话后，其他标签页、浏览器和设备会在下次正常轮询时同步移除；刷新、新开页面也会同步 Server 当前列表，不从浏览器缓存恢复旧通知。“全部关闭”只移除点击时已显示或已拉取的通知，同期新完成的任务继续保留。关闭失败会显示错误并允许重试，不提前隐藏卡片或跳转；直接从会话列表进入会话不会自动关闭通知。

Server 重启会清空内存待通知列表，数据库仅保留事件去重和传输记录，不恢复已受理的旧通知；Client 重试、重连或重启不会把已关闭的同一轮通知重新加入列表，同一会话下一轮成功完成仍正常提醒。网页关闭后无法显示卡片；子代理、已归档、失败和中断的会话不提醒。管理员和只读访问者均可接收并关闭这份共享通知列表。

## 飞书 / Lark 通知

管理员进入 **设置与访问管理 → Webhook 通知**，填写群自定义机器人的 Webhook，勾选“启用 Webhook 通知”并保存，然后点击“发送测试通知”。所有工作空间共用 Server 上的这一组配置，无 Client 在线时也可配置和测试。支持 `open.feishu.cn` 与 `open.larksuite.com`；机器人开启签名校验时填写签名密钥。可选的监控台访问地址用于在通知中加入对应工作空间和会话链接，应填写接收人能访问的地址。

主会话每一轮成功完成后，推送工作空间、会话名称、项目、完成时间（UTC+8）和最多 1,000 字符的最终回复摘要。包括从桌面版及监控台发起的会话；子代理、已归档、失败及中断的会话不推送。完成通知以轮次为单位，不等待原生目标整体完成。启用或更换接收配置时，Client 首次同步建立基线，不补发已有历史。

Client 只扫描 Codex 本地记录，将事件存入本地日志，经现有加密连接上报；Server 持久化接收、按工作空间去重后确认，由 Server 统一排队、格式化消息、签名和调用 Webhook。Client 不持有 Webhook 或签名密钥。关闭网页或退出登录不影响通知；Server 停机时 Client 保留待上报事件，重连或重启后重传。Server 已受理的通知在 Client 离线后仍可发送和重试；Client 停机期间的新完成事件恢复后继续扫描。

Codex 提出需要选择或回答的结构化问题时，发送“需要你选择或回答”提醒，包含会话、项目、题目和可选项；每次最多展示 3 个问题、每题 5 个选项，请在 Codex 中回答。支持当前桌面版的异步提问、实时记录与历史记录同步，以及旧 JSONL 的用户输入请求。按工作空间和问题 ID 持久化去重，刷新、记录同步和重启不会再次提醒同一个问题；已回答的问题跳过，Client 上报问题已处理后，Server 取消尚在等待重试的提醒。未回答的问题持续跟踪，不因超过五分钟扫描窗口取消。首次同步和重新启用时不补发已有问题。普通回复正文中的问号不会单独触发问题提醒；以最终回复提出的问题仍会通过会话完成通知推送。

配置和投递队列存入 Server 私有 `.monitor/monitor.sqlite`（自定义 `MONITOR_DATA_DIR` 时位于该目录），仅管理员可读写。接口仅返回 Webhook 地址提示和密钥是否已配置，留空保留原值；可单独移除签名密钥。真实 Webhook 不写入源码或浏览器本地存储。设置显示所有工作空间最近 20 条投递记录，包含工作空间、尝试次数、状态和失败原因。一体模式沿用已有通知配置和队列；独立 Client 升级时停用旧发送器、清除本地 Webhook 和签名密钥，需在 Server 配置统一接收地址。

每个会话轮次持久化去重，已确认成功的投递不会因刷新或服务重启重发。网络故障、HTTP 429 和服务端错误最多尝试三次；业务码错误立即显示失败。关闭通知或更换接收配置会取消等待中的投递。Webhook 不提供幂等回执，网络超时后重试可能重复；进程在发送中被终止时保留“结果未确认”的失败记录，不自动重发，需核对群消息。测试通知失败不会自动重试。

协议参考：[Lark 自定义机器人使用指南](https://open.larksuite.com/document/uAjLw4CM/ukTMukTMukTM/bot-v3/use-custom-bots-in-a-group)。

## 远程访问

默认监听本机全部网卡，可从同一可信局域网访问。跨网络使用时，将服务接到自己的 **HTTPS 反向代理或私有 VPN**；配置明确的 `MONITOR_ORIGINS=https://codex.example.com`，代理转发 `Host` 并关闭 `/api/stream` 缓冲，SSE 超时设置至少 60 秒。也可配置原生 TLS。不要把明文 HTTP 端口直接映射到公网。

Nginx 示例（证书路径按实际配置，`map` 放在 `http` 区域）：

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    '' close;
}
server {
    listen 443 ssl;
    server_name codex.example.com;
    ssl_certificate /etc/letsencrypt/live/codex.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/codex.example.com/privkey.pem;
    location / {
        proxy_pass http://127.0.0.1:9902;
        proxy_set_header Host $http_host;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_buffering off;
        proxy_read_timeout 90s;
    }
}
```

代理域名必须加入 `MONITOR_ORIGINS`，否则 Host 校验会拒绝访问。服务不信任客户端提交的 `X-Forwarded-For`；经代理的登录限速以代理 IP 合并计算。

## 安全设计与恢复

- 每个数据接口、导出和 SSE 都在服务端验证不透明随机 Bearer 令牌。令牌不放 URL；数据库只存其 SHA-256 摘要。所有 API 禁止缓存。
- 密码使用随机盐和 scrypt，服务端不存明文密码。初始化需要本机一次性密钥，完成后禁用初始化；没有公开注册。
- 异步指令和新建会话在提交前重新检查当前设备和管理员权限；指令与排队消息同时重新检查会话是否已归档。撤销设备后，尚未提交的直接控制操作不会继续执行。已受理的持久消息队列按账户权限处理，退出浏览器不会取消排队消息，需显式取消。
- 登录限速、Host 白名单、同源检查、严格输入校验、SQL 参数绑定、CSP、禁止嵌入、Markdown 原始 HTML 不执行、外部图片不加载。
- 只允许索引指向的会话 ID；文件解析前校验真实路径只能落在指定的会话目录中，阻止路径穿越和符号链接越界。没有任意文件或命令执行接口。
- 浏览器本地存储的令牌等同于登录权限，应仅在自己的设备上选择记住登录。密码及 Codex 自身的认证文件不会发送到网页。
- Windows 启动器将 `.monitor`、自行配置的 `MONITOR_DATA_DIR` 及已有凭据、数据库文件权限限制为当前 Windows 用户及 SYSTEM。数据目录必须是专用目录，不能设置为磁盘根目录、用户主目录或项目的上级目录。直接使用 `npm start` 时需自行保护数据目录。`.monitor`、构建文件和测试输出均不进入 Git。

忘记密码时，在本机项目目录执行：

```powershell
npm run account -- reset admin
```

新随机密码写入 `.monitor/initial-credentials.txt`，账户全部旧设备授权立即失效。这个命令需要本机文件访问权限，不对外提供。首次通过命令行创建账户可用 `npm run account -- bootstrap admin`。更改密码后删除旧凭据文件，或妥善保存它。

## 开发和验证

代码按功能与职责拆分，模块边界及维护约定见 [架构说明](docs/architecture.md)。前端请求与状态转换集中在 hooks，后端由组合入口装配路由和读取适配器。

完整浏览器回归启动独立 Server 和两个真实加密 WebSocket client，使用模拟 Codex 数据与控制器，覆盖多工作空间和原有功能。加密协议、双 client 隔离、重连、权限与密钥轮换另有独立集成测试。

```powershell
npm ci
npm run build
npm start
npm test
npm run test:e2e
```

开发时分别运行 `npm run dev`（接口）和 `npm run dev:web`（Vite 页面）。端到端测试自动创建独立临时 Codex 数据和独立账户，监听 `127.0.0.1:14317`，**不写入真实 Codex 数据**。Windows 优先使用已安装的 Edge；其他环境先运行 `npx playwright install chromium`。覆盖桌面与 iPhone 尺寸、持久登录、授权撤销、工具和历史查看、Markdown 安全、导出以及文件更新触发的实时同步和重连。

技术栈：React 19 / TypeScript / Vite / Express 5 / Node 内置 SQLite。无外部数据库、云服务或 OpenAI API Key 要求。

参考：[CC Switch 会话管理](https://github.com/farion1231/cc-switch) 的列表、项目分组和对话阅读交互；本项目独立实现。Codex 存储格式属于本地内部实现，升级后若格式变化可通过读取适配层调整。
