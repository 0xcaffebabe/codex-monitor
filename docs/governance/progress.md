## 执行约束

- 不使用真实会话、通知收件人或生产状态做测试；测试使用隔离 fixture。重构不自动重启运行中的 Server/client。
- 同一文件由一个实施者拥有；跨任务修改由负责人协调。所有最终提交由根代理按批次明确选取文件。
- 独立审查后运行相关行为测试；结构性改动交付前运行现有 `npm run check`。基线失败单独记录，不能把未通过检查写成通过。
- 需要产品决策、协议升级或数据破坏的事项记入任务池；其他安全任务继续。
