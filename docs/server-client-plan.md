# Server / client 实施与验收方案

## 职责

- Server 持有浏览器账户、设备授权和工作空间注册信息，提供唯一 Web 入口；不读取远程机器的 Codex 文件。
- Client 持有本机 Codex 读取器、桌面控制器、持久操作队列、上传附件、用量缓存和通知投递器，主动连接 Server 的 `/api/clients/connect` WebSocket。
- 每个 client 对应一个持久工作空间。浏览器的工作空间 API 由 Server 经该连接转发，响应及 SSE 事件沿同一连接实时返回。Client 的 HTTP 适配器仅绑定随机 loopback 端口，并使用每请求随机授权，公网不需开放 client 端口。
- 默认一体启动也创建真实 WebSocket 连接；独立 server 模式可以在没有 Codex 的机器运行；独立 client 模式不提供 Web 界面。

## 协议与隔离

- 每个工作空间具有独立固定 AES-256 密钥，分别保存在两端本地，不随连接派生或轮换；握手只发送 HMAC 签名证明，线上不传密钥。业务帧使用 AES-256-GCM、随机 IV、连接/方向/序号认证，支持手动撤销和轮换。
- 连接使用版本协商、心跳和指数退避重连；同一工作空间不允许两个活动 client 抢占。
- HTTP 请求、响应分片、消费确认、取消、权限复核具有独立关联 ID。响应逐片确认，防止慢浏览器积压；请求大小、并发和消息大小有明确上限。
- 浏览器 Bearer 密钥留在 Server。Client 只接收用户/设备身份，并通过反向 RPC 向 Server 复核权限；控制在实际提交前再次复核。断线时不自动重放已经提交的请求，沿用本机持久回执的查询语义。
- URL、草稿、附件、请求回执按工作空间隔离；切换时卸载旧工作空间并终止旧请求，浏览器其他标签页可以同时管理不同 client。
- 原有单机数据库继续用于默认本机 client，保留账户、操作回执、附件绑定、用量及通知配置。

## 验证

1. 构建及已有单元/接口测试，覆盖现有会话、控制、队列、文件和鉴权。
2. 增加真实 WebSocket 集成测试：两个独立 client、相同会话 ID、读写隔离、实时更新、附件往返、离线重连、密钥轮换、权限撤销及不确定回执。
3. 桌面和手机端到端验证登录、工作空间切换、草稿隔离、消息控制、实时事件、设置和用量；运行现有浏览器回归。
4. 使用本地浏览器验收最终界面及真实本机数据读取，测试数据和模拟 Codex 控制使用独立临时目录。

已完成：最终 `npm run check` 通过，86 项单元/接口/集成测试通过，118 项桌面/手机端到端测试通过，18 项按设备适用范围跳过。本地 Chrome 双 client 收发、独立 client 进程、本地密钥文件和真实 Codex 数据只读链路验证通过；新版一体服务已启动。
